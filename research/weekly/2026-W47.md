### 2. Long-horizon agents and durable execution
- Pillar: Software Architecture
- Source: Kiran Prakash, martinfowler.com — https://martinfowler.com/articles/durable-execution-agents.html
- Published: 2026-11-10
- Type: primary (practitioner article)
- Verified facts:
  - Durable execution: the runtime records the result of each step that
    touches the outside world; after a failure the program replays, skipping
    recorded steps.
  - Retries give at-least-once behaviour, not exactly-once, so receivers need
    idempotency keys.
  - "Durable is not the same as correct": stale decisions and outcomes the
    agent cannot see still need handling (expiry, re-checks, compensating
    actions).
  - Names Temporal, Cloudflare Workflows, Restate, Inngest and DBOS.
- Interpretation (agent's, not the user's):
  - The patterns are queueing, logging and replay applied to longer and less
    predictable jobs.
- Possible angles:
  - The user's Centrica lead-discovery searches ran 10 minutes to 1 hour on a
    queue (public profile). What did long-running AI jobs teach about
    retries, duplicates and stale results?
- Needs from the user: whether retries or failures actually caused
  duplicates or stale results, and how they were handled.

### 3. 5 Ways We Solve the CI Bottleneck
- Pillar: Software Engineering
- Source: Juri Strumpflohner, Nx Blog — https://nx.dev/blog/five-things-faster-cheaper-ci
- Published: 2026-11-11
- Type: primary, but a vendor post about its own product (Nx Cloud CI,
  described as in private beta)
- Verified facts:
  - Argument: coding agents push far more often than people and each push
    starts a CI run; faster machines are not the long-term fix; knowing the
    codebase lets CI run less.
  - Five techniques: critical-path scheduling, dynamic task packing, dynamic
    worker scaling, "Ultracache" (recording task file reads/writes as cache
    inputs/outputs), and atomization (one e2e task per test file).
  - Vendor benchmark on a 511-project monorepo: 10.6x faster and 79% less
    compute than GitHub Actions with Nx remote caching. Vendor-run; not
    independently verified. Do not quote without that caveat.
  - The post attributes a "25x more CI jobs in six months" figure to
    Anthropic. Second-hand; not checked at the original. Do not use.
- Interpretation (agent's, not the user's):
  - With agents writing code, the constraint moves from typing to
    verification.
- Possible angles:
  - The user migrated a monolithic Angular app to Nx for maintainability
    (public profile) and now does frontend work with Claude Code. Has the
    pipeline become the slow part?
- Needs from the user: their own observation, and an OK to mention using
  Claude Code for work.

### 4. Why are good developers so wary of agentic development?
- Pillar: Agentic AI and LLMs / Personal Engineering Journey
- Source: Rachel Laycock (CTO, Thoughtworks), martinfowler.com — https://martinfowler.com/rachels-ramblings/good-devs-wary.html
- Published: 2026-10-29
- Type: primary (opinion from a practitioner)
- Verified facts:
  - Argues the caution is about whether agent-built systems can be trusted in
    production, not about attachment to coding.
  - Describes a week-long experiment with agents writing all the code: about

    whiteboard, one-third to building the feedback harness; the build was
    often red and the cause was unclear.
- Possible angles:

    work: what was given up, what guardrails were needed.
- Needs from the user: their actual guardrails. Supporting source for
  post 3 this week; a standalone post later.

### 5. Tests as data: ensuring AI-generated code does what we want
- Pillar: Software Engineering
- Source: Matteo Vaccari, martinfowler.com — https://martinfowler.com/articles/tests-as-data.html
- Published: 2026-11-11
- Type: primary
- Verified facts:
  - Claims developers become the AI's customers; customer tests should be the
    contract; keeping that contract in data files (YAML/CSV tables,
    scenarios) makes it easier to protect from agents and to review.
  - States limits: tables only suit scalar inputs/outputs; tests can still
    encode wrong behaviour; hooks protecting test files are not bulletproof.
- Possible angles:
  - How does the user stop an agent from "fixing" a failing test?
- Needs from the user: their testing practice with Claude Code.
