- Source: Martin Fowler — https://martinfowler.com/fragments/2026-11-20.html

- Type: secondary (Fowler summarising others; open the originals before citing)

  - The CodeScene result could anchor a later post on code quality and agents,
    after the original write-up has been read.
- Possible angles:
  - Does messy code cost more when an agent reviews it? Open the CodeScene
    original first.
- Needs from the user: whether they have noticed agents doing worse in the

### 3. Data Contracts
- Pillar: Software Architecture
- Source: Simon Harrer and Arif Wider, martinfowler.com — https://martinfowler.com/articles/data-contracts.html
- Published: 2026-11-18
- Type: primary
- Verified facts:
  - Data contracts treat datasets "with the same rigor as an API": kept in
    Git next to pipeline code, versioned, checked automatically.
  - Uses the Open Data Contract Standard (ODCS); ODCS 3.2 added an "AI
    context" block.
  - SemVer: removing or renaming a column is breaking and needs a new major
    version published alongside the old one, with phase-in and phase-out.
  - Costs named: time to write and maintain; not for all company data;
    adoption is a cultural shift. "an agent acts on an outdated contract just
    as confidently as on a correct one."
- Interpretation (agent's, not the user's):
  - Close to the user's frontend work on data-heavy platforms: the UI is
    usually the last consumer to find out a field changed.
- Possible angles:
  - What happens to a dashboard when an upstream field is renamed, and who
    finds out first? Only if the user has a non-confidential example
    (SLB or earlier).
- Needs from the user: a real case, and an OK if it involves an employer.

- Possible angles: none recommended.
