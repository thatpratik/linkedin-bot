# A skill is more than a saved prompt

## Intended audience
Engineers and tech leads who have started using coding agents and are writing
their first skills. Takeaway: the value of a skill is in the scripts and
reference files it carries, not in the wording of its instructions.

## Hook options
1. A skill is not a prompt you saved somewhere. — #11 Myth Bust; corrects the common mental model in one line.
2. If your skills are only markdown, stop calling them skills. — #7 The Callout; sharper, but more confrontational than your past posts.
3. Good skills tell the agent what to do. Great skills give it something to run. — #16 Good vs Great; clear, slightly formulaic.

Recommended: 1, because it is short, a little dry, and closest to how your
"How's Fable treating you?" post sounds.

## Body
```text
A skill is not a prompt you saved somewhere.

Last month Anthropic handed the Agent Skills standard to the Agentic AI Foundation, the same Linux Foundation home MCP already has. Cursor, GitHub Copilot, VS Code and ChatGPT all read the format now.

The format is almost boring. A folder with a SKILL.md, plus whatever scripts and reference files the task needs.

I just built two for my team. One turns a release that used to be a list of manual steps into a single run, right down to telling the team what to test. The other knows how we review code, because it's built on a large set of our past reviews.

Instructions tell the agent what you want. A script gives it the same answer every time it runs. That's what makes the release one repeatable. A reference file means it can look something up instead of guessing.

If your skill is only instructions, it's a prompt with a folder around it. That's fine. Just don't expect it to behave like a tool.

What's in your most-used skill besides the markdown?
```
